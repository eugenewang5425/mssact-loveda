# MSSACT-Net 架构有效性分析：为什么消融实验全部"无差异"

**日期**：2026-09-12
**数据**：LoveDA `newsplit2`（train 1768 / val 221 / test_clean 141），协议 60ep/pt20/bs8/lr2e-4 + OneCycle + EMA
**依据**：全部结论均由**可复现的数值实验**支撑，脚本内联给出

---

## 0. 摘要

此前 8 个消融变体的 Kappa 全部落在 ±0.006 内，且 5 个变体**超过**完整模型。
当时的解释是"标签质量上限导致基准分辨力不足"。**该解释不完整。**

通过对 checkpoint 张量与前向传播的直接数值检验，本分析证实该模型存在**三处
结构性缺陷**，使得多个设计模块**在实现层面并未按设计意图工作**：

| # | 缺陷 | 验证方式 | 后果 |
|---|---|---|---|
| **D1** | **FPN 的多尺度融合是死计算** | 归零支路 0–2 后输出差 **恰好 0.0**；整个 FPN 可用两个卷积**逐位等价**替换 | **1,828,352 参数（全模型 29.96%）永不参与输出** |
| **D2** | **解码器无跳连**，仅凭 8× 下采样特征上采样 8 倍 | 前向代码路径 + 张量形状追踪 | 高分辨率特征（256²/128²/64²）**从未到达输出**；有效空间粒度 8×8 像素 |
| **D3** | **Transformer 无位置编码** | 置换 token 后输出按逆置换还原，差 **7.15e-07** | 模块**置换等变**，是集合级算子，**完全无空间位置感知** |

因此，"模块无贡献"不是（仅仅是）基准分辨力问题，而是**模块被消融时本来就没在
做设计声明的功能**。这解释了为什么消融结果如此平坦：被移除的东西在数值上
接近"什么都不做"。

同时，DeepLabV3+ 对自研模型的 **+0.072**（test_clean 池化 Kappa，配对 bootstrap
95% CI [+0.0525, +0.0929]，显著）也有了机制解释：DeepLabV3+ **拥有**低层跳连
（Chen et al., ECCV 2018），而这正是本模型缺失的。

**诚实定位**：本节是对自研架构的**否定性发现**，属于本项目最有价值的技术结论
之一——它把"测不出差异"从"指标不行"改写为"实现有缺陷"，并给出可直接验证的修复路径。

## 1. 参数量账目（直读 checkpoint 张量）

模型：`MSSACTNet(embed_dims=[32,64,128,256], transformer_layers=2, transformer_heads=4)`
权重：`checkpoints/full_all_v2_best.pt`（阶段 C 正式主模型）

| 模块 | 参数 | 占全模型 |
|---|---:|---:|
| **fpn** | 2,484,224 | **40.71%** |
| **transformer** | 1,612,609 | **26.43%** |
| encoder (EMR) | 1,226,504 | 20.10% |
| decoder | 722,378 | 11.84% |
| ecsam（坐标注意力） | 55,044 | **0.90%** |
| stem | 1,025 | 0.02% |
| **合计** | **6,101,784** | 100% |

**推论 1**：FPN + Transformer = **67.14%** 的参数。移除二者（D1 变体）后参数降至
**2,005,120**（−67.2%），而 Kappa 仅变化 **−0.0027**（见 §4）。
**推论 2**：坐标注意力（ECSAM）仅占 **0.90%** 参数——**先天地**不可能产生可测量的
贡献。对占比 0.9% 的模块期待显著增益，在容量意义上是不合理的。

## 2. 缺陷 D1：FPN 的多尺度融合是死计算

### 2.1 代码路径

`MSSACTNet.forward`：

```python
if self.use_fpn:
    fpn_features = self.fpn(encoder_features)
    x = fpn_features[-1]          # <-- 只取最后一层
```

`FPN.forward`：

```python
laterals = [conv(feat) for conv, feat in zip(self.lateral_convs, features)]   # L0..L3
for i in range(len(laterals) - 1, 0, -1):
    laterals[i-1] = laterals[i-1] + F.interpolate(laterals[i], size=..., mode='nearest')
outputs = [conv(feat) for conv, feat in zip(self.fpn_convs, laterals)]
return outputs
```

自顶向下循环写入的索引是 `i-1`，即 **2, 1, 0**。`laterals[3]`（最深、32²）**从未被
融合增强**。而调用方只使用 `outputs[-1]`，即 `C3(laterals[3])`。

**结论**：`laterals[0..2]` 及其对应的 `fpn_convs[0..2]` 计算完毕后被完全丢弃；
整个自顶向下融合路径（1.83M 参数）对输出**零贡献**。

### 2.2 数值验证（可复现）

```python
m  = MSSACTNet(in_channels=3, num_classes=7, embed_dims=[32,64,128,256],
               transformer_layers=2, transformer_heads=4).eval()
x  = torch.randn(1,3,256,256)
y0 = m(x)

# 检验 1：只归零 lateral_convs[0..2]（横向连接死支路）
mm = copy.deepcopy(m)
for i in (0,1,2):
    mm.fpn.lateral_convs[i].weight.zero_(); mm.fpn.lateral_convs[i].bias.zero_()
# -> 输出最大绝对差 = 0.000e+00

# 检验 2：把整个 FPN 换成"仅第 4 支路"的等价算子
#    EffFPN.forward(feats) = [fpn_convs[3](lateral_convs[3](feats[-1]))]
# -> 输出最大绝对差 = 0.000e+00
```

**两次检验均为逐位相同（0.0）**，而非"小到可以忽略"。即：**整个 FPN 模块可以被
两个卷积（1×1 与 3×3，256 通道，最深尺度）逐位等价替换。**

### 2.3 参数账目

| 项 | 参数 | 占全模型 |
|---|---:|---:|
| FPN 死参数（支路 0–2） | 1,828,352 | **29.96%** |
| FPN 有效参数（支路 3） | 655,872 | 10.75% |
| **实际参与前向的有效参数** | **4,273,432** | **70.04%** |

**因此"w/o FPN"消融的真实含义是**：移除"最深尺度上的一个 1×1 卷积 + 一个 3×3
卷积，外加 3 条被丢弃的支路"。这解释了实测 ΔKappa = **+0.0002**（0.6312 → 0.6314，
移除后**略微变好**）——移除的主要是无效计算与噪声参数。

> **这不是"FPN 冗余"的证据**，而是"**这个 FPN 没有在工作**"的证据。二者的科学
> 含义完全不同：前者是关于多尺度融合的一般结论，后者是关于本实现的缺陷结论。

## 3. 缺陷 D2：解码器无跳连，输出由 8× 下采样特征上采样而来

### 3.1 分辨率链

| 阶段 | 输出分辨率 | 说明 |
|---|---|---|
| 输入 | 256×256×3 = 196,608 | |
| stem (3×3, stride 1) | 256×256 | |
| encoder[0] + maxpool | 128×128 | |
| encoder[1] + maxpool | 64×64 | |
| encoder[2] + maxpool | 32×32 | |
| encoder[3]（无 pool） | **32×32** | ← FPN 支路 3 取此层 |
| Transformer | 32×32 → **1024 tokens** | |
| decoder：3 次转置卷积 stride 2 | 64² → 128² → 256² | **无任何跳连** |

`SegmentationDecoder.forward` 只接收单一张量 `x`：

```python
x = F.relu(self.bn1(self.upsample1(x)))   # 32 -> 64
x = F.relu(self.bn2(self.upsample2(x)))   # 64 -> 128
x = F.relu(self.bn3(self.upsample3(x)))   # 128 -> 256
return self.classifier(x)
```

**没有 U-Net 式的 encoder→decoder 跳连。** `encoder_features[0..2]`（256²/128²/64²）
虽被计算，但只经序列链影响 `encoder_features[3]`，其**高分辨率版本从未进入解码器**。

### 3.2 后果（数学上）

输出 256² 上的每个 8×8 像素块，其预测**完全由 32² 表征中的一个 token 决定**。
有效空间粒度 = **8 像素**（@0.3 m ≈ 2.4 m 地面）。在 0.3 m 数据上，这意味着模型
在结构上**无法表达比 2.4 m 更精细的边界**。

这与实测一致：
- test_clean 边界带 OA 0.4517（DeepLabV3+ 0.4657）
- 逐类 mIoU **每一项都低于 DeepLabV3+**（见 §4.2）
- mIoU 0.3229 vs DeepLabV3+ 0.4016

**文献依据**：编码器-解码器网络"若无跳连通常无法达到最优性能，U-Net 即利用编码器
特征图找回细粒度细节"；DeepLabV3+ 相对空洞金字塔的改进正是"**增加一条跳连以保留
低层图像细节**"，且其跳连**只有一条**（不同于 U-Net 的对称全跳连）。这与本模型的
缺陷形成直接对照。

## 4. 缺陷 D3：Transformer 无位置编码，是集合级算子

### 4.1 代码路径

```python
class TransformerEncoder(nn.Module):
    def __init__(self, d_model, nhead, num_layers, dim_feedforward=2048, dropout=0.1, use_adapter=True):
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=d_model, nhead=nhead, dim_feedforward=dim_feedforward,
            dropout=dropout, activation='gelu', batch_first=True)
        self.transformer = nn.TransformerEncoder(encoder_layer, num_layers=num_layers)

    def forward(self, x):
        B, C, H, W = x.shape
        x_flat = x.flatten(2).permute(0, 2, 1)     # (B, H*W, C)  <- 摊平为 token 序列
        x_trans = self.transformer(x_flat)          # <- 未加任何位置编码
        ...
```

`nn.TransformerEncoderLayer` **不自带位置编码**（不同于 ViT）。代码在摊平后、
进入注意力前**没有插入任何位置信息**。

### 4.2 数值验证（可复现）

```python
te = TransformerEncoder(d_model=64, nhead=4, num_layers=2, dim_feedforward=256, use_adapter=True).eval()
x  = torch.randn(1, 64, 8, 8)                  # 64 个 token
y  = te(x)
perm = torch.randperm(64)                       # 随机置换 token 顺序
xp   = 按 perm 重排 x 的 token
yp   = te(xp)
yp_back = 按 perm 的逆置换还原 yp 的 token
# -> |yp_back - y|.max() = 7.153e-07   (浮点噪声量级)
```

**结果表明该模块对 token 顺序完全等价（置换等变）**，即输出不依赖任何 token 的
空间位置。

### 4.3 理论依据与诚实的限定

自注意力本身是**置换等变**的：对置换矩阵 $P$，

$$A=\mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt d}\right)\;\longrightarrow\; P A P^\top$$

即注意力把 token 当作**集合**而非序列/网格。加入位置编码的作用正是打破这一对称性。

**三处必须如实说明的限定**：

1. **不等价于"该模块完全无用"。** 本模块的输入 token 来自卷积特征，其特征
   *内容*本身是位置相关的；零填充与边界也可充当隐式位置锚点（CPVT/PEG 一路的
   论证：含卷积的混合架构可以不用显式位置编码）。因此该模块仍能完成**基于内容
   相似度**的全局聚合。
2. **但它无法完成基于空间邻近的上下文建模**——而"长程空间上下文"正是分割网络
   中全局注意力的标准用途。这是一个**机制性降级**，不是彻底失效。
3. **量级参照**：位置编码并非可有可无——移除 DeiT-tiny 的位置编码使 ImageNet
   精度由 **72.2% 降至 68.2%**（检索所得，属分类任务）。故此处是实质性缺陷，
   只是其后果被卷积主干部分抵消。

**与消融结果的一致性**：移除 Transformer 实测 ΔKappa = **−0.0010**（0.6312 →
0.6302）。"在卷积特征上做一次无位置感知的全局平均式混合"贡献接近零，与上述机制
分析吻合。

## 5. 通道-空间容量比：用户直觉的数学化

用户提问："我们是 512 最大尺度，但 patch 只有 256，是否有冗余？"

**答：存在容量膨胀，且可量化。**

| 配置 | 最深特征 | 元素数 | 输入元素数 | 比值 |
|---|---|---:|---:|---:|
| light `[32,64,128,256]` | 256×32×32 | 262,144 | 196,608 | **1.33×** |
| large `[64,128,256,512]` | 512×32×32 | 524,288 | 196,608 | **2.67×** |

即：**最深特征图的标量数量超过输入图像本身**（large 配置达 2.67 倍）。而这些表征
最终被压缩回 256² 输出，且其中 **29.96% 的参数不参与前向**（§2）。

注意此处**并非** transformer 的秩亏问题：token 数 $N=32^2=1024 > d_{model}$，故
$\mathrm{rank}\le\min(N,d_{model})=d_{model}$，不存在因 $d_{model}>N$ 导致的秩瓶颈。
问题在于**空间侧信息量 vs 通道侧容量的失衡**：以 8 像素的粒度承载 256–512 通道。

## 6. 与实验结果的对应关系

### 6.1 消融为何平坦（机制解释）

| 变体 | 实测 ΔKappa | 机制解释 |
|---|---:|---|
| w/o FPN | **+0.0002** | FPN 支路 0–2 是死计算（§2）；移除的只是无效计算 + 最深尺度两个卷积 |
| w/o Transformer | **−0.0010** | 置换等变集合算子（§4）；在卷积特征上做无位置感知的聚合 |
| w/o ECSAM | **−0.0040** | 该模块仅占 **0.90%** 参数（§1） |
| w/o Adapter | **+0.0030** | 仅 33K 参数的缩放残差（0.54%） |
| Bilinear-Up | **+0.0057** | 解码器无跳连（§3），learnable 与 bilinear 上采样差别仅在内核参数化 |
| 联合移除 FPN+Trans(+Adapter) | **−0.0027 / −0.0035** | 上述机制叠加 |

*（前 5 行为阶段 C 的 `nd_abl_*`，联合移除为两条管线各一次：PNG 管线 0.6312→0.6277，
回退管线 0.6320→0.6293）*

**关键推论**：**没有一个消融变体削弱了它声称削弱的功能**，因为对应功能在实现中
本就不存在（FPN）或不可用（Transformer 的位置感知）。因此这一组消融**不能**
作为"模块有效性"的证据——它衡量的是"移除无效计算的影响"。

### 6.2 基线为何领先

test_clean（141 张）池化 Kappa 与配对 bootstrap（1000 次图像级重采样）：

| 模型 | 参数 | Kappa | Δ vs 自研 | 95% CI | 判定 |
|---|---:|---:|---:|---|---|
| **DeepLabV3+** | 39.69M | **0.6495** | **+0.0720** | [+0.0525, +0.0929] | 显著差异 |
| FPN-Seg | 27.20M | 0.5440 | −0.0335 | [−0.0432, −0.0231] | 显著差异 |
| FCN | 23.78M | 0.5416 | −0.0358 | [−0.0453, −0.0264] | 显著差异 |
| U-Net | 2.45M | 0.5348 | −0.0426 | [−0.0532, −0.0318] | 显著差异 |
| Swin-Unet | 32.67M | 0.5041 | −0.0734 | [−0.0891, −0.0564] | 显著差异 |
| **MSSACT-Net (自研)** | **6.10M** | **0.5774** | — | — | 参考 |

逐类 mIoU（test_clean）：

| | back | build | road | water | barren | forest | agri | mIoU | mIoU(去barren) |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|

**公平性核验（重要）**：有人会怀疑基线享有 ImageNet 预训练优势。**已核对代码**：
`deeplabv3_resnet50(weights=None)`、`resnet50(weights=None)`、`resnet18(weights=None)`
—— **全部从零训练**，与自研模型同协议同数据。故该 +0.072 是公平对比下的真实差距，
最可能的解释是 DeepLabV3+ 具备本模型缺失的**低层跳连**（§3）与保留分辨率的空洞卷积。

## 7. 边界/Kappa 归属：为什么"边界质量"在聚合指标上不可见

逐图（2D）修正后的边界统计（详见 `fix_boundary_analysis.py`）：

| 距类边界 | 像素占比 | 共识 vs 标签 | 模型间分歧 |
|---|---:|---:|---:|
| 0（边界像素） | **2.36%** | 0.4577 | 0.2881 |
| 1–2 px | 5.34% | 0.4891 | 0.2877 |
| 3–4 px | 5.17% | 0.5327 | 0.2847 |
| 5–8 px | 8.75% | 0.5882 | 0.2789 |
| **>8 px（内部）** | **78.39%** | 0.7294 | 0.2294 |

**Kappa 归属上限**（oracle 作弊实验，六模型一致）：

| 模型 | K_base | 完美解决边界 | Δ边界 | 完美解决内部 | Δ内部 |
|---|---:|---:|---:|---:|---:|
| MSSACT-Net | 0.5774 | 0.5936 | **+0.0161** | 0.8700 | **+0.2925** |
| DeepLabV3+ | 0.6495 | 0.6654 | +0.0159 | 0.8800 | +0.2306 |
| FPN-Seg | 0.5440 | 0.5602 | +0.0162 | 0.8644 | +0.3204 |
| FCN | 0.5416 | 0.5579 | +0.0163 | 0.8615 | +0.3199 |
| U-Net | 0.5348 | 0.5512 | +0.0163 | 0.8644 | +0.3296 |
| Swin-Unet | 0.5041 | 0.5211 | +0.0170 | 0.8587 | +0.3546 |

**结论**：完美预测全部边界像素（2.36%）**最多**换来 **+0.016** Kappa；内部像素
（78.39%）则值 **+0.23 ~ +0.35**。**聚合 Kappa 主要由内部区域的语义分类决定**，
而边界锐化类模块（多尺度融合、坐标注意力、可学习上采样）的可见空间被限制在
≈0.016 以内——与观测到的消融散布 0.006 **同量级**。

与此同时，DeepLabV3+ 优势的分带归因显示 **86.6% 的 ΔOA 来自内部像素**
（内部 +0.0529 / 合计 +0.0611），边界带仅贡献 +0.0003。故其优势同样是
"内部区域语义分类"能力，而非边界定位能力。

## 8. 可验证的修复路径

| 优先级 | 修复 | 预期效果 | 验证方式 |
|---|---|---|---|
| **P0** | FPN 改为**真正使用**多尺度输出（解码器接收 `fpn_features` 全部 4 层，或至少做跳连） | 恢复多尺度融合语义；释放 1.83M 无效参数的用途 | 消融应出现可测差异 |
| **P0** | 解码器加入 **encoder→decoder 跳连**（U-Net 式或 DeepLabV3+ 单条低层跳连） | 直接修正 §3 的粒度瓶颈（8 px → 可达 1–2 px） | 边界带 OA 应显著上升 |
| **P1** | Transformer 加入**位置编码**（2D sincos / 可学习 / 相对位置偏置），或改为窗口注意力 | 恢复空间邻近建模能力 | 置换等变性检验应被打破 |
| **P1** | 依据 §6.1 重新定义消融语义：先修复实现，再评估"模块是否有效" | 使消融结论可解释 | — |
| **P2** | 容量重新配比：通道侧下调 / 空间侧保留，修正 2.67× 容量膨胀 | 参数效率 | 参数量-Kappa 曲线 |

## 9. 诚实的局限

1. **随机种子方差尚未测量。** 本分析中所有 ΔKappa 均来自**单次运行**（seed=42）。
   文献建议 ≥10 个种子（GEO-Bench, NeurIPS 2023 D&B），并指出 3–5 个种子不足以
   给出可靠置信区间；mmseg 实测同一 DeepLabV3+ 两次训练即可相差 0.7 mIoU
   （双线性插值反向非确定）。
   **因此"ΔKappa 0.006 落在噪声内"这一判断目前是推断，不是测量。**
   多种子队列（完整模型 + DeepLabV3+ × 3 个种子）已在 `run_queue_final.py` 中排队。
2. **等效性检验尚未完成。** 严格区分"无证据有差异"与"有证据无差异"需要 TOST
   （预指定 SESOI）。本节已实现配对 bootstrap CI；待 22 个变体的推理缓存完成后
   补齐 TOST。
3. §2/§3/§4 的缺陷检验在 **light 配置**上完成；大配置 `[64,128,256,512]` 结构相同，
   结论可直接推广，但未逐一复跑。
4. 本节的 Kappa 归属与分带结论基于**已缓存的 6 个模型预测**；8 个消融变体的逐带
   分解待推理缓存完成后补齐（同一队列）。
