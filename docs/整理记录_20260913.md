# 项目目录整理记录（2026-09-13）

> 本次整理的目标：**脚本与产物分离、结果集中归档、路径依赖集中化**，
> 并保证整理后**全部脚本仍可直接运行**（有实跑验证，见第五节）。

---

## 一、整理原则

1. **路径集中化**：所有脚本一律通过 `paths.py` 的常量取路径。
   这样今后再次重组目录，**只需改 `paths.py` 一处**，不必逐个脚本改。
   本次整理正是按这条原则做的，也当场验证了它的价值（见第三节）。
2. **脚本 / 产物 / 数据三层分离**：
   - 脚本 → 按用途分 7 个子目录
   - 实验结果 → 统一收进 `results/`
   - 报告图 → 单独 `figures/`（需入库，与结果区分）
3. **入库 / 不入库的判据**：可复现生成的（权重、memmap、预测数组、HTML）不入库；
   权威事实（`FACTS.json` / `experiments_index.json` / `seed_variance.json`）与
   汇总性统计（各类 `*_summary.json`、`*_conf.json`）入库。
4. **历史产物不删、只归档**：移入 `_local_archive/` 或 `legacy/`，保持可追溯。

## 三、路径依赖适配（本次最关键的一步）

### 3.1 核心机制

`paths.py` 是所有路径的唯一来源：

```python
RESULTS  = <repo>/results          # 全部结果的总目录（可用 LDA_RESULTS 覆盖）
CKPT     = results/checkpoints     # 权重与训练历史
FAST_DATA= results/fast_dataset    # 预解码 memmap
CONSENSUS= results/consensus_analysis
FIGURES  = <repo>/figures          # 报告图（与结果分开，需入库）
... （其余同构）
```

### 3.2 修改清单

| 位置 | 原 | 新 |
|---|---|---|
| `paths.py` | 各常量直指仓库根 | 统一挂到 `RESULTS` 下；新增 `RESULTS` / `FAST_DATA` |
| `.env`（本地，不入库） | `LDA_CKPT=...\loveda\checkpoints` | `...\loveda\results\checkpoints`；新增 `LDA_RESULTS` |
| `train_v3.py` | `fast_dir` 默认 `<同目录>/fast_dataset` | `paths.FAST_DATA` |
| `prep/build_fast_dataset.py`、`prep/build_ladder_memmap.py` | `paths.REPO/"fast_dataset"` | `paths.FAST_DATA` |
| `queues/` 4 个脚本 | `os.path.join(BASE,"checkpoints")` | `paths.CKPT` |
| `queues/{arch,deeplab_scr,deeplab_protocol}` | `paths.REPO/"fast_dataset"/...` | `paths.FAST_DATA/...` |
| `analysis/{eval_ladder,consensus_analysis}.py`、`queues/monitor_queue.py`、`queues/run_queue_{30m,interaction}.py`、`verify/verify_experiments.py`、`viz/make_figures.py`、`viz/make_stats_figures.py` | `f"{BASE}/checkpoints"` 等 f-string | `paths.CKPT` / `paths.LADDER_EVAL` / `paths.CONSENSUS` / `paths.FULLTILE` / `paths.HELDOUT` / `paths.TTA` / `paths.FIGURES` |
| `report/build_facts.py` | `CKPT/TT/CONS/overfit_diag/artifacts` 五处 f-string | 全部改为 `paths.*` |
| `verify/bench_parity.py`、`bench_pipeline.py`、`sample_gpu_now.py` | `paths.REPO/"artifacts"` | `paths.RESULTS/"artifacts"` |

共 **12 个脚本、22 处引用**被修正。`legacy/` 内的旧脚本未改（已归档、不运行）。

### 3.3 一个真实踩到的坑（值得记录）

`.env` 里的 `LDA_CKPT` 用的是 **Windows 反斜杠**路径。我用脚本替换时写入了
`...\loveda\results\checkpoints`，其中 `\r` 被当成**回车符**，把路径截断成
`...\loveda` + 换行 + `esults\checkpoints` → `paths.CKPT` 解析成仓库根目录。

**修法**：`.env` 统一改用**正斜杠**（Windows 同样接受），并在文件头注明原因，
彻底回避各类脚本中的转义问题。

## 六、给后续维护的提示

1. **新增结果目录**：在 `paths.py` 里加常量，指向 `RESULTS/xxx`；
   脚本里用该常量，不要写 `f"{BASE}/xxx"`。
2. **再次重组目录**：只改 `paths.py`（以及 `results/` 内部的实际移动），
   然后**务必重跑第五节的验证表**——特别是 `build_facts` 是否仍无 null。
3. **`.env` 一律用正斜杠**，避免反斜杠转义。
4. **不要**把结果目录直接放在仓库根：`results/` 之外的根目录应只有
   核心模块、脚本子目录、文档与三项权威事实。
