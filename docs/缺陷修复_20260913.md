## 一、缺陷清单（全部有数值证据）

| 编号 | 缺陷 | 证据 | 量级 |
|---|---|---|---|
| D1 | FPN 多尺度融合是死计算 | 归零 `lateral_convs[0..2]` 后输出**逐位不变**（diff = 0.0）；等价算子替换整个 FPN 亦为 0.0 | 1,828,352 个参数（真实参数的 29.9772%）收不到梯度 |
| D2 | 解码器无 encoder→decoder 跳连 | `SegmentationDecoder.forward(self, x)` 只接收单个张量；256²/128²/64² 特征从未到达输出 | 上采样 8 倍全靠转置卷积合成 |
| D3 | Transformer 无位置编码 | 置换 token 后按逆置换还原，残差 7.153e-07 ⇒ 置换等变 | 无空间位置感知 |
| **D5（本次新增）** | `ecsam[0]` 是死模块 | 构造时 4 个阶段全建，前向条件是 `i > 0`，故第 0 个恒不执行；实测其 7 个张量 `.grad is None` | 1,040 个参数（0.017%） |

D1/D2/D3 原载于 `docs/架构有效性分析.md`；D5 为本次补测发现，属同一类「模块建好但没接线」缺陷。

**参数口径更正**：报告此前引用的 **6,101,784 是 `state_dict` 总元素数**，含 16 层 BatchNorm2d 的
2,640 个 buffer（running_mean / running_var / num_batches_tracked）。
**真实 `nn.Parameter` 数量 = 6,099,144（6.0991M）**，旧口径高估 **0.0433%**。
以真实参数为分母：FPN 死参数占 **29.9772%**（此前记 29.9642%），有效参数 **4,270,792 = 70.02%**（此前 70.04%）。结论方向不变。

## 二、修复设计：向后兼容开关

修改集中在 `models/msscactnet.py`，**新增三个开关，默认值 == 修复前行为**：

| 开关 | 作用 | 修复 | 参数量 |
|---|---|---|---|
| `use_skip=True` | 解码器逐级接入主干同分辨率特征；有 FPN 时接入 FPN 的四级输出（**同时修好 D1**：死支路变活），无 FPN 时接入编码器浅三层 | D1+D2 | 6.0991M → 6.4643M（+5.99%） |
| `pos_enc=True` | Transformer 注入 2D 正弦位置编码 | D3 | 不变 |
| `ecsam_stage0=True` | 第 0 阶段也应用 ECSAM | D5 | 不变（本次未启用） |

**为什么坚持向后兼容**：既有 103 个实验的 checkpoint 必须仍能以 `strict=True` 加载、既有结论必须仍可复现。
牺牲的是参数账目的整洁（`ecsam[0]` 的 0.017% 死参数被有意保留，见第四节）。

### 跳连结构

```
FPN 输出四级: f0(256²×256) f1(128²×256) f2(64²×256) f3(32²×256)
解码器输入 x = f3
  up1: 32²×256 --转置卷积--> 64²×128  --cat proj(f2)--> 64²×192  --3×3 conv--> 64²×128
  up2: 64²×128 --转置卷积--> 128²×64  --cat proj(f1)--> 128²×96  --3×3 conv--> 128²×64
  up3: 128²×64 --转置卷积--> 256²×64  --cat proj(f0)--> 256²×96  --3×3 conv--> 256²×64
  classifier: 256²×64 -> 256²×num_classes
```
跳连侧先 1×1 降维（256→64/32/32）再拼接，新增 363K 参数（+5.99%）。
尾部通道数（256²×64）与分类头保持原样，故 `classifier` 无需改动。

## 三、验证证据（五项，全部通过）

对照物为修复前的旧版副本（`models/msscactnet.py.bak_20260913_2054`）。

| 验证项 | 结果 |
|---|---|
| **1. 默认路径逐位一致** | 默认配置 `strict=True` 加载旧权重成功；新旧输出最大逐元素差 **0.000e+00**（不是"很小"） |
| **2. 键集合一致** | `mssact_light()` 与 `lgR_bs8_full_lr2e4_best.pt` 键集合完全相同，参数量同为 6,099,144 |
| **3. 置换等变性被打破** | 残差 `pos_enc=False` 9.537e-07 → `pos_enc=True` 1.821e+00（放大约 190 万倍） |
| **4. 梯度可达性** | 基线无梯度参数 29.99% → `use_skip=True` 后仅剩 `ecsam[0]` 的 0.017%；`skip_*` 全部收到梯度 |
| **5. 组合路径** | 10 种消融组合（含 bilinear / no_fpn / no_trans / trans4l / trans6l / decoder_ca）× 跳连，输出形状与梯度完整性全部通过 |

### 3.1 修复过程中踩到的两个坑（已写入记忆）

1. **跳连通道约定的方向**。`_fuse(x, skips, k)` 取 `skips[len-1-k]`，即 k=0 用**最深**的跳连，
   故 `skip_channels` 必须是**深→浅（使用顺序）**。初版写成浅→深，**在有 FPN 时被掩盖了**——
   因为 FPN 四级输出恰好都是 256 通道，通道数相同；到 `use_fpn=False` 才炸出
   `expected 32 channels, got 128`。
2. **不要用 `F.interpolate` 兜底跳连的空间尺寸**。兜底会把"跳连层级接错"这种语义错误
   悄悄抹平成一条能跑但错误的通路。现改为显式 `assert`（空间尺寸 + 通道数各一条），
   约定错误立刻报错。

## 四、修复后仍存在的死参数（如实记录）

`ecsam_stage0=False`（默认）时，`ecsam[0]` 的 1,040 个参数仍不参与前向。
**不修它的原因**：不构造它会导致 `self.ecsam[i]` 索引整体错位，且旧 checkpoint 无法 `strict=True` 加载。
**可复现性优先于参数账目的整洁**，故保留并显式记录。
需要"零死参数"时用 `ecsam_stage0=True`（实测无梯度参数 0 项）。

## 五、实验设计：为什么必须重跑基线

### 5.1 60 轮与 120 轮不可直接比较

OneCycle 的收敛轮次由**退火终点**决定（best@49 对应 60 轮、best@109 对应 120 轮，见
`docs/` 中的 OneCycle 分析）。故"60 轮 OneCycle"与"120 轮 OneCycle"是**两个不同的学习率调度**，
其 Kappa 差值混合了「调度变化」与「训练量」两种效应。

⇒ 修复归因必须有**同为 120 轮**的基线 `lgR120_full`。新建可比组 **G4-MEM-ROLL-120ep**，
并在 `build_index.py` 里写明**禁止**把 G4 与 G2（60ep）相减当作"预算效应"。

### 5.2 队列

`queues/run_queue_fix.py`，12 个实验 × 120 轮（pt20 / bs8 / lr2e-4），实测 43–59 s/轮，约 18–21 小时。

- **阶段一（修复归因，4 个）**：`lgR120_full`（基线） / `lgR120_fx_skip`（修 D1+D2） / `lgR120_fx_pos`（修 D3） / `lgR120_fx_all`（全修）
- **阶段二（修复后消融，8 个）**：`lgR120_abl_{no_emr, no_ecsam, no_fpn, no_trans, no_adapter, bilinear, trans4l, trans6l}`，
  全部以 `use_skip=True + pos_enc=True` 为底 —— 这是**首次可解释的消融**，模块作用不再被缺陷掩盖。

判别门限沿用 σ_seed = 0.0050（n=4）：|Δ| ≥ 2σ = 0.0100 记为可分辨。

## 六、修复过程中新发现的两个问题

### 6.1 测试集协议此前只覆盖了一半结论（已修）

`results/consensus_analysis/pred_{tag}.npz` 存在**两种不兼容布局**：

- 旧布局 `(564, 256, 256)` —— `consensus_analysis.py` 时代产物
- 新布局 `(141, 1024, 1024)` —— 与 `labels.npz` 一致，`eval_rigor` 的口径

`eval_rigor` 遇到形状不符会 `跳过`。因此以下 tag **从未进入测试集协议**（逐波段 / 伪影 / 等效性）分析：
**G1 的 8 个消融（`nd_abl_*`）、`lg_D1..D4`、`lgR_D1..D4`、`nd_pspnet`、`nd_segformer`**。

后果：报告中关于消融的结论此前**只有 val Kappa 单一来源**，没有测试集侧的独立证据。
修复：新增 `queues/run_post_fix.py` 显式列出全部 44 个 tag 做全量推理，并在覆盖前把
consensus 目录整体备份到 `results/_local_archive/`。

### 6.2 等效性检验此前只有打印、没有产物（已修）

`eval_rigor.py` 里已有配对 bootstrap 与 TOST 判定，但**只 print，不落盘**——报告无法引用、
无法复现，新增 tag 也不会自动扩展。
修复：新增 `analysis/tost_equivalence.py`，把判定落成 `results/artifacts/tost_equivalence.json`，
并**复用 `eval_rigor` 的度量函数**（不重复实现，避免口径漂移）。

### 6.3 由 6.2 得到的一条实测结论（推翻了我的先验估计）

我原先在脚本里写下断言："141 张测试集的图像级配对 bootstrap 的 CI 半宽约 ±0.02，宽于 SESOI=0.02，
故 TOST 在此误差模型下给不出等效结论"。**实测推翻**：

| 对照对 | ΔKappa | boot 95% CI | 半宽 |
|---|---:|---|---:|
| nd_unet vs full_all_v2 | −0.0426 | [−0.0532, −0.0318] | 0.0107 |
| nd_fcn vs full_all_v2 | −0.0358 | [−0.0453, −0.0264] | 0.0095 |
| nd_deeplab vs full_all_v2 | +0.0720 | [+0.0525, +0.0929] | 0.0202 |
| nd_fpn_seg vs full_all_v2 | −0.0335 | [−0.0432, −0.0231] | 0.0101 |
| nd_swin_unet vs full_all_v2 | −0.0734 | [−0.0891, −0.0564] | 0.0164 |

**配对设计**（两个模型跑同一批图）使 Δ 的方差远小于各自 Kappa 的方差，故 CI 半宽 δ ≈ 0.010 量级，
**小于** SESOI = 0.02 ⇒ 测试集层**足以**给出等效判定。
两个误差模型量级接近（种子层 ±0.010，测试集层 ±0.011），脚本对两者并列报告、不合并成单一阈值。
